# CrossCommitVuln-Bench：複数コミットにまたがり per-commit 静的解析では不可視な Python 脆弱性のデータセット
https://arxiv.org/abs/2604.21917v1

## institutions


## summary
本論文は CrossCommitVuln-Bench を提示する。これは実世界の Python 脆弱性（15件の CVE）を収集・注釈したベンチマークで、脆弱性条件が複数のコミットに分散して導入され、各コミット単独では per-commit の静的解析ツールに検出されないケースに焦点を当てる。各 CVE に対して寄与コミット列・“なぜ各コミットが per-commit 解析を回避するか” の構造化された理由付けを手作業で付与し、Semgrep と Bandit による per-commit と累積スキャンのベースライン評価を示す。主要知見として、コミット単位検出率は全体で 13%、累積スキャンでも 27% に留まり、スナップショットベースの SAST が複数コミットで導入される脆弱性を取りこぼすことを示す。データセット、注釈スキーマ、評価スクリプトを OSS として公開している。

## impact_level: High

## why_matters
- ソフトウェアサプライチェーンと CI/CD に対する実践的リスクを明確化：複数コミットにまたがる脆弱性やバックドアは、ノード実装、オフチェーンインフラ、ウォレット、オラクルなど Web3 の重要コンポーネントに直接的な被害を与え得るため、これを検出・防止する技術・サービスは高い投資価値がある。
- 既存の SAST・自動化ツールの限界を実証：スナップショット／per-commit に依存する検査では見落としが多く、市場にはコミットチェーン解析、差分追跡、履歴ベースの静的解析等の高度化ツールや監査サービスの需要があることを示している。
- 研究・製品開発の土台を提供：再現可能なデータセットとベースラインにより、跨コミット検出アルゴリズム（履歴的データフロー解析、継続的セキュリティ監査、サプライチェーンフォレンジクス）の研究・プロダクト化が促進され、将来的に Web3 セキュリティ製品への組み込みが容易になる。
- 留意点—適用範囲とスケール：サンプルは Python の実例 15 件と規模は小さく、直接スマートコントラクト言語（Solidity/Rust/Vyper）に関する成果ではないが、オフチェーン基盤やデプロイパイプライン保全の観点からは実務的に高い関連性がある。

- DA（データ可用性）ギャップとプロトタイプ未完成の点は採用リスクを示すため、DA向上ソリューションや部分実装への初期投資機会（ミドルウェア、オーケストレーション、専用ハードウェア）は高いポテンシャルを持つ。
